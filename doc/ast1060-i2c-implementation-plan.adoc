== Project Overview

**Objective:** Integrate the AST1060 I2C driver with the Hubris I2C API framework to enable both master and slave mode operations.

**Current State:**
- ✅ Low-level AST1060 hardware driver (`drv/ast1060-i2c`)
- ✅ Generic I2C server framework (`drv/openprot-i2c-server`)
- ✅ I2C API definitions (`drv/i2c-api`, `drv/i2c-types`)

**Gap:**
- ❌ Hardware adapter implementing `I2cHardware` trait
- ❌ Software message buffering for slave mode
- ❌ Server integration and configuration
- ❌ Testing infrastructure

**Success Criteria:**
1. Application tasks can use I2C master mode via standard API
2. Application tasks can receive I2C slave messages via notifications
3. Message loss rate < 0.1% under normal load
4. Latency < 25µs from hardware interrupt to client notification
5. All unit and integration tests pass

```rust
impl From<I2cError> for ResponseCode {
    fn from(err: I2cError) -> Self {
        match err {
            I2cError::NoAcknowledge => ResponseCode::NoDevice,
            I2cError::Timeout => ResponseCode::ControllerBusy,
            I2cError::Invalid => ResponseCode::BadArg,
            I2cError::InvalidAddress => ResponseCode::BadSlaveAddress,
            I2cError::BusError => ResponseCode::BusError,
            I2cError::ArbitrationLost => ResponseCode::BusError,
            I2cError::SlaveError => ResponseCode::SlaveConfigurationFailed,
            I2cError::InvalidController => ResponseCode::BadController,
        }
    }
}
```

```rust
// In interrupt handler
fn i2c_interrupt() {
    for controller in 0..14 {
        if has_slave_interrupt(controller) {
            driver.handle_slave_interrupt(controller);
            
            // Notify subscribed client
            if let Some((task, mask)) = get_notification_info(controller) {
                sys_post(task, mask);
            }
        }
    }
}
```

== Risk Management

=== Risk 1: Hardware Availability
**Probability:** Medium
**Impact:** High
**Mitigation:**
- Use QEMU or simulator for initial development
- Mock hardware for unit tests
- Order/reserve hardware early

---

=== Risk 2: Interrupt Latency Too High
**Probability:** Low
**Impact:** Medium
**Mitigation:**
- Profile interrupt handler early
- Optimize critical path
- Consider DMA if available

---

=== Risk 3: Buffer Overflow in Production
**Probability:** Medium
**Impact:** Medium
**Mitigation:**
- Conservative buffer sizing (8 messages)
- Monitor drop statistics
- Document tuning procedures

---

=== Risk 4: Integration Issues with Server
**Probability:** Low
**Impact:** High
**Mitigation:**
- Early integration testing
- Clear interface contracts
- Incremental integration

---

=== Risk 5: Hardware Bugs or Errata
**Probability:** Low
**Impact:** High
**Mitigation:**
- Review AST1060 errata early
- Test with known-good I2C devices
- Have workarounds documented
